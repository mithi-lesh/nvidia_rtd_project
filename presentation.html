Why This Problem Matters

Mining remains one of the world's most hazardous industries. Workers need instant, reliable access to approved safety procedures — not generic internet searches.

dangerous

The Problem

  • Safety manuals are lengthy PDFs (100s of pages), hard to search during emergencies
  • Workers cannot quickly locate specific SOPs for blasting, PPE, or evacuation
  • Generic AI chatbots may hallucinate incorrect safety procedures — risking lives
  • No existing system answers mine-safety queries from verified, organization-approved documents
lightbulb

Our Solution

  • A RAG-based chatbot that retrieves answers only from uploaded, approved safety manuals
  • Source citations with every answer (document name + page number) for verifiability
  • Hallucination prevention: refuses to answer if info is not in the approved documents
  • Fully offline & local — ideal for mine sites with restricted or no internet

Key Design Decisions

  1. Offline-first: Ollama runs locally — no API keys, no cloud, no internet required at inference time.
  2. Overlap chunking (150 chars): Prevents context from being cut mid-sentence at chunk boundaries.
  3. BGE-small embeddings: Only 384 dimensions — fast, memory-efficient, yet top-tier retrieval accuracy.
  4. Decoupled architecture: React frontend can be deployed independently from the Django API backend.

Core Implementation Details

Hallucination Prevention Prompt

# System prompt enforces factual grounding PROMPT = """You are a Mine Safety Assistant. Context from approved manuals: ----- {context} ----- Question: {question} Instructions: - Answer ONLY using the provided context. - If the context does not contain the answer, clearly state it is unavailable. - Cite the source document and page. - Do NOT guess or fabricate procedures. """

Vector Retrieval (Cosine Similarity)

from pgvector.django import CosineDistance def retrieve_context(query, top_k=4): query_embedding = get_embedding(query) chunks = Chunk.objects.order_by( CosineDistance( 'embedding', query_embedding ) )[:top_k] return list(chunks)

PDF Ingestion Pipeline

import fitz # PyMuPDF def ingest_pdf(file_path, doc_instance): with fitz.open(file_path) as pdf: for page_num in range(len(pdf)): text = pdf[page_num].get_text("text") chunks = chunk_text(text) for chunk in chunks: embedding = get_embedding(chunk) Chunk.objects.create( document=doc_instance, page_number=page_num + 1, content=chunk, embedding=embedding )

Database Schema (pgvector)

CREATE TABLE documents ( id BIGSERIAL PRIMARY KEY, title TEXT, category TEXT, file TEXT, uploaded_at TIMESTAMP ); CREATE TABLE chunks ( id BIGSERIAL PRIMARY KEY, document_id BIGINT REFERENCES documents, page_number INT, content TEXT, embedding VECTOR(384) -- pgvector );

Conclusion

The Mine Safety RAG Assistant successfully demonstrates that Retrieval-Augmented Generation can provide accurate, citation-backed, and hallucination-free answers to safety-critical questions in mining, oil, and gas industries.

By running entirely offline with a local LLM (Ollama) and using Supabase pgvector for semantic search, the system is uniquely suited for deployment in connectivity-restricted mine environments.

Key Contributions

  • First RAG system specifically targeting mine/oil/gas safety SOP documents
  • Enforced hallucination prevention through constrained prompting
  • Complete source traceability for every generated answer
  • Fully offline architecture suitable for underground deployments
  • Admin self-service portal for non-technical safety officers
  • Emergency SOS protocol system with evacuation checklist
